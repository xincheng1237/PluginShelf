# PluginShelf · 插件架

macOS 音频插件资料库、批量备份与可还原删除工具。1.1 版本，支持 macOS 14+，Universal 2（Apple 芯片与 Intel）。

## 开始使用

从 [Releases](https://github.com/xincheng1237/PluginShelf/releases) 下载 1.1 DMG，打开安装镜像，将 PluginShelf 拖入“应用程序”，再打开。应用启动后只扫描，需用户完成两步确认才会移动插件。未安装后台服务，扫描与分类离线进行，不上传插件资料。

- 侧边栏按效果器、虚拟乐器、其他、未识别、插件格式或最近添加筛选；表格列标题可排序。
- 在右侧详细信息或表格右键菜单中选择“设置分类…”，可为单项或多项设置多个分类，或恢复自动识别。手动设置在重新扫描和重启后保留，不改写插件文件。
- 工具栏搜索名称、厂商、标识符及路径，空格分词采用全部匹配。
- 列表侧边 A–Z / # 字母索引用于快速定位，中文名称使用拼音首字母。点击字母会切回 A–Z 排列并快速滚动，不隐藏其他插件。
- 排序菜单支持名称 A–Z / Z–A、添加时间从新到旧 / 从旧到新、大小从大到小 / 从小到大。表头排序与菜单状态联动。
- 左右侧栏开关的按下状态反映侧栏是否展开。
- “近 N 天”使用文件系统添加日期，缺失时回退到创建日期。该日期不代表经验证的安装日期；首次发现日期另行记录。
- 按 ⌘ 或 Shift 多选，或点“选择结果”选择当前全部结果。
- 可在设置中增加专用插件目录。移除扫描目录不会删除插件。

## 类型识别

自动读取 AU/AUv3 的 AudioComponents 声明、VST3 可选的 moduleinfo.json（包含 JSON5 与旧位置）、LV2 的 manifest.ttl 及包内关联 Turtle 文件。不加载插件代码，不根据名字猜类型。LV2 目前支持常见声明语法与标准分类，未实现完整 RDF 推理；不读取包外文件或网络元数据。

接收 MIDI 的 AU 效果器 aumf 仍归类为效果器；AU aumu 归类为虚拟乐器，发生器/MIDI 工具等归入其他。VST3 兼具 Fx/Instrument 标签时同时列入两类，控制器不计为音频组件。缺少声明时，先检查本机同产品 AU/AUv3/VST3 的完整单组件分类：产品标识、名称与版本均需匹配；已核实的显式标识别名支持 Melodyne 等跨格式标识不同的产品。关联只使用原始声明，不传播手动设置或其他推断结果，多组件、混合用途、冲突结果不会直接套给另一种格式。

没有可用关联时，查找应用内置的已核实资料库（2026.10.21）：33 个产品记录，首批覆盖 Avid 常用 AAX、Melodyne 5 和 TDR Nova 2。资料库严格核对 Bundle ID、格式、名称和适用主版本，不按文件名关键词或厂商整体猜测。Avid 记录目前适用主版本 25；未知新主版本需核实后更新。资料库离线随应用发布，不联网更新。仍缺乏依据的插件显示未识别，可以手动修正。

详细信息区分“插件声明”“已核实资料”和“关联其他格式”，显示来源、关联文件和官方参考链接；点击资料链接才会使用浏览器访问厂商网站。本版不加载插件代码。参见 `docs/CLASSIFICATION_CATALOG.md`。

分类可以重叠，因此侧栏各分类数量之和可能大于插件文件数。单个包内存在无法识别的组件时，该包也列入“未识别”。详细信息展示声明来源、已读取的组件清单；手动分类不会覆盖原始声明展示。分类记录仅保存在应用自己的 category-overrides.json，按安装路径与 Bundle ID 匹配；更换同路径但不同 Bundle ID 的插件不会继承旧设置。移动到另一条安装路径后需重新设置。

无论当前按哪种类型筛选，备份和删除都以整个文件包为单位；删除第一页列出可读取的同包组件并提示整个包一起移除。未识别的包内组件也会一起移除。

## 备份与恢复

选择插件，点“备份所选”，导出 `PluginShelf-日期-数量.pluginshelfbackup`。这是带原路径清单和逐插件 SHA-256 校验的文件夹包，可以放入网盘或其他磁盘。

原生 Finder 会把备份目录显示为一个文档包；需要查看内部时可使用“显示包内容”。可用 Finder 的“压缩”功能打包 ZIP，恢复前请完整下载并解压。

点“从备份恢复”或双击 `.pluginshelfbackup`，验证后先查看清单，再恢复原位置。同名插件会跳过而不覆盖；每项失败都会报告原因。跨电脑路径不一致时，需要先登记原路径；首版不自动映射不同用户名。

备份只包含插件文件，不包含外置采样库、独立预设、许可证、安装器及共享运行库。厂商插件在另一台电脑仍可能需要重新安装与授权。插件文件本身的校验不等于厂商签名或来源验证。

## 删除与系统废纸篓（1.1）

移除插件仍需清单核对、输入数量和勾选确认。文件通过 macOS 官方 `FileManager.trashItem` 接口移入系统废纸篓；应用只记录自己移入的项目，不枚举整个废纸篓，不注册登录项或后台清理服务。

系统的 30 天清理是可选设置：Finder → 设置 → 高级 →“30 天后移除废纸篓中的项目”。该设置影响整个系统废纸篓，PluginShelf 不修改它；手动清空或立即删除可能提前移除插件。应用不承诺插件一定保留满 30 天，也不再自行计算和执行到期清理。

应用内“废纸篓”可查看删除记录、多选还原，或经过两步确认后永久删除所选项目。还原会校验内容，遇到原位置同名文件时不覆盖。系统已清除、Finder 已移出或所在磁盘暂不可访问的项目保留记录并禁用文件操作；不可用的系统废纸篓记录可以单独移除，移除记录不会删除文件。

通过持久书签、卷与文件身份追踪项目，删除前重新确认文件仍在对应卷的系统废纸篓且内容未变化。文件已移出或被替换时，不追着它删除。

![1.1 废纸篓（演示数据）](docs/trash-1.1-demo.jpg)

1.0 的应用内废纸篓 `~/Library/Application Support/PluginShelf/Recovery` 保持原位，仍可还原或手动永久删除，不再自动清理。新记录单独存放于 `SystemTrashRecords`，避免旧版本读取或清理新记录。升级前请先退出旧版应用。

## 覆盖与当前限制

| 格式/类型 | 行为 |
| --- | --- |
| AU / VST2 / VST3 / AAX / CLAP / LV2 / RTAS | 扫描标准用户、共享、网络目录及自定义目录，按独立文件/Bundle 管理 |
| AUv3 | 查看 `/Applications` 与 `~/Applications` 中应用自带扩展；不拆包、不单独备份或删除 |
| macOS 系统自带组件 | 不扫描、不显示 |
| 顶层符号链接 | 只读；混合选中只读项时批量操作禁用 |
| 宿主内置效果、JSFX、脚本、ReFill、专有资源库 | 本版未完整覆盖，不承诺发现所有类型 |
| WaveShell 等多插件壳 | 按壳文件显示，不加载代码枚举壳内每个音色或效果 |

当前版本没有管理员授权辅助程序。读写遵守当前用户权限；共享目录若需要管理员权限，会明确失败。不会修改系统目录权限、自动提权或删除授权数据。此版本尚未 Developer ID 签名和公证，不作为对外正式发行包。

## 工程

原生 SwiftUI + AppKit；Swift 6 严格并发，独立 Core target 与串行文件操作 actor。应用无第三方运行依赖。构建与维护步骤见 [CONTRIBUTING.md](CONTRIBUTING.md)。

```sh
swift test
./Packaging/build.sh
./Packaging/dmg.sh
```

只安装 Command Line Tools 也能构建。构建脚本分别生成 arm64/x86_64 再合并，使用本地 ad-hoc 签名。`BUILD_DIR` 和 `APP_OUTPUT` 可指定输出目录。

DMG 额外使用构建工具 `dmgbuild==1.6.5`：`python3 -m pip install --target work/dmg-design/tools dmgbuild==1.6.5`。它只负责磁盘映像和 Finder 布局，不随应用交付。`Packaging/dmg.sh` 生成带 1×/2× 原生字体背景的拖拽安装界面，安装说明 TXT 单独输出；`DMG_OUTPUT` 可指定镜像路径。

设计与动画遵循本次应用的 `emil-design-eng`、`animate` Skill。详见 `docs/DESIGN_REVIEW.md`；验证范围详见 `docs/VERIFICATION.md`。
